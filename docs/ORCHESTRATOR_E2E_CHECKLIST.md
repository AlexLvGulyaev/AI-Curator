# Orchestrator — E2E чек-лист функциональных проверок

## Цель

Проверить, что настройки консоли **Orchestrator** реально влияют на поведение публичного чата AI Curator. Каждый пункт — это сквозной сценарий: изменение конфигурации + вопрос студента + ожидаемый ответ системы.

## Предусловия

- Admin Console открыт на вкладке **Orchestrator**: `https://curator-admin.alex-n8n.site`.
- Web UI студента открыт на отдельной вкладке: `https://curator.alex-n8n.site`.
- В Knowledge Base загружены материалы по курсу, а в Moodle есть курс с дедлайнами и прогрессом.
- После каждого изменения конфигурации нажимается **Сохранить**. Кэш чата сбрасывается автоматически.
- Перед каждым тестом в Web UI чата начинается **новая сессия** (если требуется чистая история).

## Известные ограничения

1. **Priority** влияет только на интенты, определённые через `conditions`. `deadline` и `progress` определяются по keywords раньше и не участвуют в сравнении priority.
2. **`intent_max_tokens`** — soft limit для LLM. Модель постарается не превысить его, но не гарантирует заполнение.
3. **`max_lms_contents`** ограничивает количество LMS-элементов в prompt LLM. На детерминированные ответы deadline/progress/подсчёты он не влияет.

## 8. Уровни сложности (difficulty)

### 8.1 beginner vs advanced — разница в ответах видна

**Предусловие:**
- В настройках AI & Retrieval есть отдельные инструкции для `beginner` и `advanced`.
- `advanced` инструкция требует структурированного углублённого ответа с таблицей сравнения, примерами кода, Big-O, edge cases и практическими нюансами.

**Настройка:**
- Default intent: `study`.
- Source routing для `study`: `RAG = true`, `LMS = false`, `Strict = false`.
- В Knowledge Base загружены материалы по теме вопроса.

**Вопрос студента (один и тот же для обоих уровней):**
> Объясни разницу между списком и словарём.

#### 8.1a — Уровень «Базовый» (`beginner`)

**Ожидаемый результат:**
- Ответ короткий, понятный без технического жаргона.
- Приведены простые примеры (`[1, 2, 3]` и `{"имя": "Алексей"}`).
- Объяснены основные отличия: порядок/индекс vs ключ-значение.
- Без таблиц, Big-O и деталей реализации.

**Фактический результат ДО изменения промпта:**
> Списки и словари — это два основных типа данных в программировании, которые используются для хранения коллекций элементов. Давайте разберём их различия.
> 
> Список — это упорядоченная коллекция элементов. Пример: `[1, 2, 3, 4]`. Элементы доступны по индексу, начиная с 0.
> 
> Словарь — это неупорядоченная коллекция пар "ключ-значение". Пример: `{"имя": "Алексей", "возраст": 25}`. Элементы доступны по ключу.
> 
> Основные отличия: списки — последовательности, словари — пары ключ-значение; доступ по индексу vs по ключу; списки упорядочены, словари — нет.

**Статус ДО:** ⚠️ PASS с замечанием. Уровень beginner отвечает корректно, но advanced-ответ практически не отличается.

#### 8.1b — Уровень «Углублённый» (`advanced`)

**Ожидаемый результат:**
- Ответ структурирован: таблица сравнения по критериям.
- Примеры кода на Python.
- Упомянута сложность операций (Big-O): поиск в списке O(n), поиск в словаре O(1) в среднем.
- Edge cases: изменение размера во время итерации, хешируемость ключей.
- Практический нюанс: когда что использовать.

**Фактический результат ДО изменения промпта:**
> Списки и словари — это два основных типа данных в программировании, которые используются для хранения коллекций элементов. Давайте разберём их различия более подробно.
> 
> Список — это упорядоченная коллекция элементов. Пример: `[1, 2, 3, 4]`. Элементы доступны по индексу. Использование: подходит для последовательностей, где важен порядок.
> 
> Словарь — это неупорядоченная коллекция пар "ключ-значение". Пример: `{"имя": "Алексей", "возраст": 25}`. Элементы доступны по ключу. Использование: идеален для быстрого обращения по ключу.
> 
> Основные отличия: списки — последовательности, словари — пары ключ-значение; доступ по индексу vs по ключу; списки упорядочены, словари — нет.

**Проблема ДО:** Разница между `beginner` и `advanced` состояла только в одном общем предложении («более подробно») и блоках «Использование». Ни таблиц, ни кода, ни Big-O, ни edge cases.

**Изменение промпта:**
- Обновлен `DEFAULT_ADVANCED_INSTRUCTIONS` в `src/services/ai_config.py`:
  - Было: "Давай углублённый ответ: детали реализации, edge cases, сравнения подходов, практические нюансы."
  - Стало: "Дай структурированный углублённый ответ: таблица сравнения, примеры кода на Python, сложность операций (Big-O), edge cases, когда что использовать, практические нюансы. Примеры должны быть техническими и конкретными."

**Ожидаемый результат ПОСЛЕ изменения промпта:**
- advanced-ответ содержит таблицу сравнения, примеры кода на Python, Big-O, edge cases.
- Разница между beginner и advanced становится визуально и содержательно заметной.

**Статус ПОСЛЕ:** 🔄 Требует повторного прогона после деплоя.
