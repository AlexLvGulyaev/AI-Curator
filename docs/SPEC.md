## 🎯 1. Назначение продукта

### 🎯 1.1. Цель

AI Curator — самостоятельная AI-подсистема образовательной платформы, которая помогает студентам:

- ориентироваться в структуре курса;
- получать сведения о расписании, заданиях и дедлайнах;
- находить ответы в учебных материалах;
- разбирать сложные темы;
- получать дополнительные рекомендации с учётом уровня подготовки;
- понимать, на каком источнике основан ответ.

### ⚠️ 1.2. Решаемая проблема

| Проблема | Последствие |
|----------|-------------|
| Информация о дедлайнах и заданиях разрознена | Студенты пропускают сроки |
| Сложные темы требуют повторного объяснения | Преподаватель тратит время на однотипные вопросы |
| Новичкам трудно понять, с чего начать | Высокий уровень отсева и неудовлетворённости |
| Студенты не знают, где искать проверенную информацию | Распространяются устаревшие или неточные данные |
| Учебные материалы не связаны с LMS-контекстом | AI даёт общие ответы без персонализации |

### 💡 1.3. Решение

AI Curator предоставляет студенту **отдельный публичный Web UI**, развёрнутый на VPS и доступный по собственному HTTPS-эндпоинту, где он может:

- задать организационный вопрос и получить точный ответ из LMS;
- попросить объяснить учебный материал простыми словами или углублённо;
- получить персональную рекомендацию с учётом прогресса и текущего модуля;
- видеть источник каждого факта — ссылку на материал Knowledge Base или задание в LMS;
- оценить полезность ответа.

Преподаватель продолжает управлять курсом в LMS. Администратор и методист AI Curator управляют Knowledge Base, конфигурацией AI и аналитикой в Admin Console.

## 🎬 3. Пользовательские сценарии

### 🏫 Сценарий 1: Организационный вопрос

**Кто:** Студент (гостевой demo-роль или аутентифицированный пользователь)
**Цель:** Узнать дедлайн, расписание или статус задания

**Шаги:**
1. Студент открывает Web UI AI Curator.
2. В режиме demo выбирает роль (`active_student`, `late_student`, `new_student`) или входит через LMS.
3. Вводит вопрос: «Когда нужно сдать третье задание?»
4. Backend проверяет сессию и доступ к курсу.
5. Backend классифицирует запрос как организационный.
6. Backend через LMS Adapter получает задание, дедлайн и статус из LMS.
7. Backend формирует ответ со ссылкой на задание в LMS.
8. Студент видит ответ, источник и может оценить полезность.

**Источники данных:** LMS API.

**Компоненты:** Web UI → Backend → LMS Adapter → LMS → Backend → Web UI.

### 📖 Сценарий 2: Учебный вопрос

**Кто:** Студент (гостевой demo-роль или аутентифицированный пользователь)
**Цель:** Понять тему, которую не удалось разобрать самостоятельно

**Шаги:**
1. Студент выбирает уровень сложности: «Начинающий» или «Продвинутый».
2. Задаёт вопрос: «Объясни разницу между списком и словарём.»
3. Backend определяет курс, модуль, тему и уровень пользователя.
4. Backend через LangChain выполняет retrieval по Knowledge Base.
5. Backend отбирает лекции, методички и FAQ.
6. Backend формирует RAG-контекст, Prompt Builder собирает промпт, а LLM Adapter выполняет единственный вызов модели.
7. Backend проверяет ответ и цитаты.
8. Студент получает ответ со ссылками на материалы Knowledge Base.
9. Студент может оценить полезность ответа (1–10) или сообщить об ошибке.

**Источники данных:** Knowledge Base AI Curator.

**Компоненты:** Web UI → Backend → LangChain Retrieval → Chroma → Prompt Builder (Backend) → LLM Adapter (Backend) / LangChain → LLM → Backend → Web UI.

### 🔀 Сценарий 3: Смешанный вопрос

**Кто:** Студент
**Цель:** Получить персональную рекомендацию с учётом ближайшего задания

**Шаги:**
1. Студент спрашивает: «Что мне повторить перед заданием, которое нужно сдать в пятницу?»
2. Backend одновременно:
   - через LMS Adapter получает задание, дедлайн и прогресс студента;
   - через LangChain находит связанные лекции и методические материалы в Knowledge Base.
3. Backend объединяет контекст.
4. Backend через Prompt Builder собирает промпт, а через LLM Adapter выполняет единственный вызов модели.
5. Backend проверяет ссылки.
6. Студент получает персональную рекомендацию.

**Источники данных:** LMS API + Knowledge Base.

**Компоненты:** Web UI → Backend → (LMS Adapter → LMS) + (LangChain Retrieval → Chroma) → Prompt Builder (Backend) → LLM Adapter (Backend) / LangChain → LLM → Backend → Web UI.

### 📊 Сценарий 4: Запрос о собственном прогрессе

**Кто:** Студент
**Цель:** Узнать свой прогресс по курсу

**Шаги:**
1. Студент спрашивает: «Какие модули я уже прошёл?»
2. Backend проверяет личность.
3. Backend через LMS Adapter получает разрешённые данные прогресса из LMS.
4. Backend формирует ответ только на основе данных текущего пользователя.
5. Студент видит персонализированный ответ.

**Источники данных:** LMS API.

**Компоненты:** Web UI → Backend → LMS Adapter → LMS → Backend → Web UI.

### ⚠️ Сценарий 5: Недостаточно данных

**Кто:** Студент
**Цель:** Получить честный ответ при отсутствии достоверных источников

**Шаги:**
1. Студент задаёт вопрос, по которому нет данных в LMS и Knowledge Base.
2. Backend не придумывает ответ.
3. Backend сообщает, какого контекста не хватает.
4. Backend предлагает релевантные материалы, если они найдены.
5. Backend рекомендует обратиться к преподавателю.
6. Backend фиксирует вопрос для анализа.

**Источники данных:** Системный prompt и бизнес-правила.

**Компоненты:** Web UI → Backend → Prompt Builder (Backend) / LangChain → Web UI.

### 📥 Сценарий 6: Добавление материала в Knowledge Base

**Кто:** Администратор / Методист AI Curator
**Цель:** Наполнить Knowledge Base учебным материалом

**Шаги:**
1. Администратор открывает Admin Console.
2. Загружает документ.
3. Заполняет метаданные: курс, модуль, тема, тип материала, уровень сложности, статус публикации.
4. Backend сохраняет исходный документ, регистрирует карточку, ставит задачу обработки.
5. Backend извлекает текст, разбивает на фрагменты, создаёт embeddings, обновляет векторный индекс.
6. Backend фиксирует результат.
7. Материал становится доступен для ответов после успешной обработки и публикации.

**Источники данных:** Knowledge Base.

**Компоненты:** Admin Console → Backend → Хранилище документов + PostgreSQL + Chroma → Admin Console.

### 🔄 Сценарий 7: Обновление материала

**Кто:** Администратор / Методист AI Curator
**Цель:** Заменить версию документа в Knowledge Base

**Шаги:**
1. Администратор открывает карточку документа.
2. Загружает новую версию.
3. Backend сохраняет новую версию, выводит старую версию из активного индекса.
4. Backend выполняет повторную обработку.
5. Backend обновляет векторный индекс.
6. Backend публикует новую версию и сохраняет историю изменений.

**Источники данных:** Knowledge Base.

**Компоненты:** Admin Console → Backend → Хранилище документов + PostgreSQL + Chroma → Admin Console.

### 🤖 Сценарий 8: Управление поведением AI Curator

**Кто:** Администратор AI Curator
**Цель:** Настроить стиль ответов, ограничения, параметры retrieval и маршрутизацию запросов

**Шаги:**
1. Администратор открывает Admin Console → AI & Retrieval Configuration.
2. Изменяет системные инструкции, правила адаптации сложности, параметры retrieval, модель LLM, fallback-поведение.
3. Backend версионирует конфигурацию и фиксирует изменения в журнале аудита.
4. В Admin Console → Orchestrator Configuration администратор настраивает intent-классификацию, source routing, token budgets и fallback-сообщения.
5. Backend сбрасывает Response Cache, чтобы изменения применились к новым запросам.
6. Новая конфигурация применяется к последующим запросам.

**Источники данных:** Операционная база AI Curator.

**Компоненты:** Admin Console → Backend → PostgreSQL → Admin Console.

### 📈 Сценарий 9: Аналитика и управленческие отчёты

**Кто:** Администратор / Преподаватель AI Curator
**Цель:** Понять, какие темы вызывают вопросы, и улучшить Knowledge Base

**Шаги:**
1. Администратор открывает Admin Console → Analytics.
2. Видит распределение запросов по темам, модулям, курсам.
3. Видит вопросы без ответа, популярные материалы, оценки полезности, задержки, ошибки.
4. Может отфильтровать по периоду и курсу.
5. В разделе Reports видит Quality Reports (answered rate, cache hit rate, RAG coverage) и Business Reports (KB gaps, expansion candidates).
6. Экспортирует отчёты в CSV для офлайн-анализа.

**Источники данных:** Операционная база AI Curator.

**Компоненты:** Admin Console → Backend → PostgreSQL → Admin Console.

### 📊 Сценарий 10: Мониторинг, логи и аудит

**Кто:** Администратор AI Curator
**Цель:** Контролировать доступность компонентов, диагностировать запросы и отслеживать административные действия

**Шаги:**
1. Администратор открывает Admin Console → Dashboard / Monitoring.
2. Видит состояние Backend, LMS-интеграции, Knowledge Base, векторного индекса, доступность LLM.
3. Видит последние ошибки, краткую аналитику и KPI.
4. В Operational Logs просматривает запросы студентов, intent, latency, источники, cache hit.
5. В Dialog Sessions видит историю диалогов, execution timeline и JSON-снимки.
6. В Audit Log видит изменяющие административные действия и публичные chat-запросы.
7. Экспортирует operational logs, audit log и dialog sessions в CSV.

**Источники данных:** Операционная база AI Curator, health endpoints.

**Компоненты:** Admin Console → Backend → PostgreSQL / LMS / Chroma / LLM → Admin Console.

**Источники данных:** LMS API, Knowledge Base, LLM API.

**Компоненты:** Web UI → Backend → DemoLimiter → LMS Adapter / RAG / LLM → Web UI.

| ID | Правило | Обоснование |
|----|---------|-------------|
| BR-1 | LMS является единственным Source of Truth для учебного процесса | Все данные о курсах, модулях, пользователях, заданиях, дедлайнах, расписании, прогрессе и оценках берутся из LMS |
| BR-2 | Knowledge Base AI Curator является самостоятельным источником учебных материалов | Knowledge Base не является частью LMS и управляется через Admin Console AI Curator |
| BR-3 | AI Curator работает с LMS API в режиме read-only | Запрет изменений исключает риски повреждения данных LMS |
| BR-4 | AI Curator не выставляет оценки | Требование заказчика |
| BR-5 | AI Curator не изменяет расписание, дедлайны, задания и курсы | Требование заказчика |
| BR-6 | Векторный индекс является производным от Knowledge Base и восстанавливаемым | Chroma / векторный индекс не является самостоятельным источником истины |
| BR-7 | AI Curator не формирует факты, отсутствующие в доступных источниках | Контроль качества и достоверности |
| BR-8 | Backend — единый оркестратор системы | Все пользовательские и административные сценарии проходят через Backend |
| BR-9 | LangChain используется только внутри Backend | LangChain не является отдельным сервисом или архитектурным слоем |
| BR-10 | Пользовательские интерфейсы не обращаются напрямую к LMS, Knowledge Base, векторному индексу или LLM | Все внешние обращения маршрутизируются через Backend |
| BR-11 | Все публичные сервисы доступны по HTTPS | Требование безопасности и доверия |
| BR-12 | Web UI AI Curator — отдельный публичный сервис на VPS | Web UI не является частью Moodle и не встраивается в LMS-интерфейс |

## 🚀 6. Нефункциональные требования

### ⏱️ 6.1. Производительность

| ID | Требование | Значение |
|----|------------|----------|
| NFR-1 | Время ответа AI на типовой вопрос (response cache hit) | p50 ≤ 5 секунд |
| NFR-1a | Время ответа AI при холодном старте (cache miss + embedding cache miss + LLM cold call) | p95 ≤ 8 секунд |
| NFR-2 | Время индексации одного документа Knowledge Base | ≤ 2 минут |
| NFR-3 | Время синхронизации метаданных при публикации | ≤ 10 секунд |
| NFR-4 | Доступность сервиса | 99.5% |

### 🔐 6.2. Безопасность

| ID | Требование |
|----|------------|
| NFR-5 | API-ключи и токены LMS хранятся только в переменных окружения; `.env` не коммитится |
| NFR-6 | Публичный Web UI не имеет прямого доступа к LMS API |
| NFR-7 | Все внешние endpoints работают только по HTTPS |
| NFR-8 | Административные endpoints требуют аутентификации и авторизации; demo-роль read-only |
| NFR-9 | Студент не может видеть данные других студентов |
| NFR-10 | Backend не раскрывает системные инструкции и внутренний контекст |
| NFR-11 | Demo-запросы не влияют на боевые лимиты и не создают долгосрочных сессий |

### 🏗️ 6.3. Масштабируемость и сопровождаемость

| ID | Требование |
|----|------------|
| NFR-12 | Архитектура позволяет в будущем подключить другую LMS через LMS Adapter |
| NFR-13 | Векторный индекс может быть полностью перестроен из документов Knowledge Base |
| NFR-14 | Конфигурация AI версионируется и фиксируется в журнале аудита |
| NFR-15 | История административных действий сохраняется в журнале аудита |
| NFR-16 | Hot-логи хранятся 30 дней, LLM traces — 7 дней; устаревшие записи архивируются в gzip |
| NFR-17 | Конфигурация Orchestrator версионируется и применяется без перезапуска сервиса |

## ✅ 7. Критерии приёмки

### ✅ 7.1. Общие критерии

| Критерий | Признак |
|----------|---------|
| Студент может задать вопрос и получить ответ | Web UI отображает ответ без ошибок |
| Ответ содержит ссылку на источник | Под ответом есть ссылка на материал Knowledge Base или задание LMS |
| AI не выставляет оценки | При запросе «выставь зачёт» система отказывает вежливо |
| AI не меняет расписание | При запросе «перенеси дедлайн» система отказывает вежливо |
| AI не придумывает ответ | При отсутствии источников система сообщает о недостатке данных |

### 📚 7.2. RAG-критерии

| Критерий | Признак |
|----------|---------|
| Поиск находит релевантные материалы | При вопросе по теме в топе есть лекция или методичка по этой теме |
| Фильтры по метаданным работают | Можно ограничить поиск модулем, темой, типом ресурса, уровнем сложности |
| Индексация учитывает версии | Повторная публикация новой версии заменяет старую в активном индексе |
| Снятие с публикации работает | Документ со статусом «не опубликован» не участвует в retrieval |

### 📊 7.3. Аналитика и мониторинг

| Критерий | Признак |
|----------|---------|
| Запросы логируются | В PostgreSQL появляются записи с вопросом, ответом, источниками |
| Аналитика по темам доступна | Admin Console показывает распределение по темам |
| Мониторинг состояния доступен | Admin Console показывает статус Backend, LMS, Knowledge Base, LLM |

## 📦 8. Границы первой производственной версии

### ✅ Входит в первую версию

- Развёртывание Moodle и AI Curator на VPS.
- Backend AI Curator с LMS Adapter, RAG через LangChain, prompt pipeline, answer validation, logging, analytics, audit.
- Knowledge Base с поддержкой лекций, методичек, FAQ, метаданных, версий и публикации.
- Web UI AI Curator — отдельный публичный сервис на VPS с HTTPS, demo-режим с квотами.
- Admin Console AI Curator для управления Knowledge Base, AI-конфигурацией, Orchestrator Config, Analytics, Reports, Logs, Dialog Sessions, Audit.
- Базовые роли: студент, администратор AI Curator, методист AI Curator, demo-администратор (read-only).
- Read-only интеграция с Moodle.
- ResponseCache с инвалидацией при мутациях.
- CSV-экспорт логов и retention policy.
- E2E-тестирование ключевых сценариев.
- Документация и материалы для портфолио.

### ❌ Не входит в первую версию

- Интеграция с несколькими LMS одновременно (архитектурно готово, но не реализуется).
- Многоязычный интерфейс (первый язык — русский).
- Мобильное приложение.
- Голосовой ввод и синтез речи.
- Интеграция с внешними мессенджерами.
- Автоматическая генерация оценок или отчётов успеваемости.
- Расширенная ролевая модель преподавателя с аналитикой (подготавливается архитектурно).
